# 安卓仿《雷电》(1990) 游戏开发计划

## 一、原版雷电核心特征分析

### 1.1 游戏概况
| 项目 | 内容 |
|------|------|
| 原版名称 | Raiden (雷電) |
| 发行时间 | 1990年9月 |
| 开发商 | Seibu Kaihatsu |
| 游戏类型 | 纵版卷轴射击 (Vertical Scrolling Shooter) |
| 关卡数量 | 8关 + 无限循环 |
| 游戏模式 | 单人 / 双人合作 |
| 故事背景 | 2090年地球遭外星人Cranassians入侵 |

### 1.2 核心玩法机制
- **操控方式**：方向杆控制飞机移动，两个按键（射击+炸弹）
- **射击系统**：无限子弹自动射击，按住即连发
- **炸弹系统**：数量有限的全屏清敌武器，有投放延迟
- **武器升级**：收集掉落道具升级主武器和副武器
- **死亡惩罚**：死亡后武器清零，但会掉落1-2个道具帮助恢复
- **合机系统**：双机重叠触发超强星星攻击（雷电标志性设计）
- **循环机制**：通关8关后从第1关重新开始，敌人射速和密度增加

### 1.3 武器系统详解
```
主武器（两种，道具颜色切换选择）：
├── 红色/Vulcan Cannon：散射子弹，覆盖面广，升级后扇形扩散
└── 蓝色/Laser：集中光束，单体高伤害，升级后光束变粗

副武器（两种）：
├── 普通导弹：直线向前发射
└── 追踪导弹：自动追踪最近敌人

道具掉落机制：
├── 特定敌机被击毁后掉落道具图标
├── 图标在中央区域漂浮并循环变色（红↔蓝等）
└── 拾取时根据当前颜色升级对应武器
```

### 1.4 敌人类型
| 类型 | 描述 |
|------|------|
| 小型战机 | 成群出现，直线或波浪飞行 |
| 中型机 | 有特定攻击模式，可能掉落道具 |
| 地面部队 | 坦克、炮台等地面目标 |
| 大型战舰 | 血量厚，有固定弹幕模式 |
| Boss | 每关末尾出现，多阶段攻击模式 |

### 1.5 视觉风格特征
- 90年代经典像素美术（Pixel Art）
- 深色太空/夜空背景搭配鲜艳弹幕色彩
- 爆炸效果醒目，带碎片飞散
- 地面场景有地形滚动效果
- HUD包含：分数、生命数、炸弹数、武器等级
- 经典的CRT扫描线视觉效果

## 二、开发技术选型

### 2.1 推荐方案：Android原生开发

| 技术栈 | 推荐理由 |
|--------|---------|
| **语言** | Kotlin（现代Android首选） |
| **游戏框架** | 纯Android Canvas API 或 LibGDX |
| **渲染** | SurfaceView + 自定义绘制 |
| **音效** | Android SoundPool + MediaPlayer |
| **数据存储** | SharedPreferences（本地排行榜） |
| **打包** | Android APK/AAB |

### 2.2 替代方案对比
```
方案A：纯Android Canvas（推荐初学者）
优点：轻量、无需额外依赖、完全掌控渲染流程
缺点：需自行处理碰撞检测、粒子效果等

方案B：LibGDX框架（推荐有游戏开发经验者）
优点：跨平台、内置物理/碰撞/粒子系统、丰富的游戏工具
缺点：学习曲线、包体增大

方案C：Unity（推荐复杂游戏）
优点：强大的编辑器和工具链
缺点：包体大、对2D像素游戏有些过重
```

### 阶段四：敌人系统（第4-6周）

#### 3.4.1 基础敌人类型
| 敌人类型 | 外观 | 移动模式 | 攻击方式 | 血量 |
|---------|------|---------|---------|------|
| 小型战机 | 小型飞行器 | 直线或正弦波 | 无或单发子弹 | 低 |
| 中型战机 | 较大飞行器 | 固定航线 | 2-3发子弹 | 中 |
| 轰炸机 | 大型机体 | 缓慢直线 | 扇形子弹 | 中高 |
| 地面坦克 | 坦克造型 | 静止 | 向上炮弹 | 中 |
| 炮台 | 固定炮塔 | 静止 | 定向子弹 | 中 |

#### 3.4.2 敌人生成系统
- [ ] 设计敌人生成波次（Wave）系统
- [ ] 实现敌人出场动画（从屏幕外飞入）
- [ ] 设计不同类型敌人的组合波次
- [ ] 实现难度递增（随关卡/时间增加敌人密度和射速）

#### 3.4.3 敌人AI行为
```
敌人行为模式：
├── 直线型：从上方直线向下飞出屏幕
├── 波浪型：正弦波横向摆动
├── 瞄准型：移动到玩家X坐标后射击
├── 环绕型：围绕某点做圆周运动
├── 冲刺型：快速冲向玩家位置
└── 停留型：停留在屏幕上方向下射击
```

#### 3.4.4 交付物
- 多种敌人在屏幕上按波次出现
- 敌人有不同移动和攻击模式
- 击毁敌人有爆炸动画和音效

### 阶段五：Boss战系统（第6-7周）

#### 3.5.1 Boss设计规格
```
每关Boss设计要素：
├── 巨大体型（占屏幕1/3~1/2）
├── 多阶段血量（血条显示）
├── 阶段转换时改变攻击模式
├── 多种弹幕组合：
│   ├── 环形散射弹
│   ├── 直线速射
│   ├── 追踪弹
│   ├── 激光扫射
│   └── 弹幕封锁网
├── 弱点部位高亮
└── 被击毁时多段爆炸动画
```

#### 3.5.2 Boss战流程
- [ ] Boss出场动画（从屏幕上方缓缓出现）
- [ ] 第一阶段攻击模式（较低密度弹幕）
- [ ] 血量70%：转换攻击模式
- [ ] 血量40%：进入狂暴模式，弹幕密度增加
- [ ] 血量10%：最终爆发攻击
- [ ] 被击败：多段爆炸+道具大量掉落

#### 3.5.3 交付物
- 至少1个完整的Boss战可用
- 多阶段攻击模式切换
- 华丽的Boss爆炸效果

### 8.1 游戏主循环（Kotlin）
```kotlin
class GameThread(
    private val surfaceView: GameSurfaceView,
    private val surfaceHolder: SurfaceHolder
) : Thread() {

    private var running = false
    private val targetFPS = 60
    private val targetFrameTime = 1000 / targetFPS

    fun setRunning(isRunning: Boolean) {
        running = isRunning
    }

    override fun run() {
        var startTime: Long
        var frameTime: Long

        while (running) {
            startTime = System.currentTimeMillis()

            var canvas: Canvas? = null
            try {
                canvas = surfaceHolder.lockCanvas()
                synchronized(surfaceHolder) {
                    surfaceView.update() // 更新游戏逻辑
                    surfaceView.render(canvas) // 渲染画面
                }
            } catch (e: Exception) {
                e.printStackTrace()
            } finally {
                canvas?.let { surfaceHolder.unlockCanvasAndPost(it) }
            }

            // 帧率控制
            frameTime = System.currentTimeMillis() - startTime
            if (frameTime < targetFrameTime) {
                sleep(targetFrameTime - frameTime)
            }
        }
    }
}
```

### 8.2 玩家战机类（Kotlin）
```kotlin
class Player(
    private val context: Context,
    private val screenWidth: Int,
    private val screenHeight: Int
) {
    var x: Float = screenWidth / 2f
    var y: Float = screenHeight - 200f
    var isAlive: Boolean = true
    var lives: Int = 3
    var bombs: Int = 3
    var weaponLevel: Int = 1
    var weaponType: WeaponType = WeaponType.VULCAN

    private val speed = 8f
    private val width = 64f
    private val height = 64f
    private var shootTimer = 0
    private val shootInterval = 8 // 每8帧发射一次

    private val bitmap: Bitmap = BitmapFactory.decodeResource(
        context.resources, R.drawable.player_red_1
    )

    fun update(touchX: Float, touchY: Float) {
        // 跟随触摸位置移动（平滑插值）
        x += (touchX - x) * 0.15f
        y += (touchY - y) * 0.15f

        // 边界限制
        x = x.coerceIn(width / 2, screenWidth - width / 2)
        y = y.coerceIn(height / 2, screenHeight - height / 2)

        // 自动射击计时
        shootTimer++
    }

    fun shouldShoot(): Boolean {
        if (shootTimer >= shootInterval) {
            shootTimer = 0
            return true
        }
        return false
    }

    fun getBullets(): List<Bullet> {
        val bullets = mutableListOf<Bullet>()
        when (weaponType) {
            WeaponType.VULCAN -> {
                when (weaponLevel) {
                    1 -> bullets.add(Bullet(x, y - 30, 0f, -12f))
                    2 -> {
                        bullets.add(Bullet(x - 15, y - 20, 0f, -12f))
                        bullets.add(Bullet(x + 15, y - 20, 0f, -12f))
                    }
                    3 -> {
                        bullets.add(Bullet(x, y - 30, 0f, -12f))
                        bullets.add(Bullet(x - 20, y - 20, -2f, -11f))
                        bullets.add(Bullet(x + 20, y - 20, 2f, -11f))
                    }
                    else -> {
                        bullets.add(Bullet(x, y - 30, 0f, -12f))
                        bullets.add(Bullet(x - 25, y - 20, -3f, -11f))
                        bullets.add(Bullet(x + 25, y - 20, 3f, -11f))
                        bullets.add(Bullet(x - 15, y - 15, -1f, -11f))
                        bullets.add(Bullet(x + 15, y - 15, 1f, -11f))
                    }
                }
            }
            WeaponType.LASER -> {
                bullets.add(Bullet(x, y - 30, 0f, -15f, isLaser = true, 
                    laserWidth = 8 + weaponLevel * 4))
            }
        }
        return bullets
    }

    fun draw(canvas: Canvas) {
        if (!isAlive) return
        canvas.drawBitmap(
            bitmap,
            x - width / 2,
            y - height / 2,
            null
        )
    }

    fun getHitbox(): RectF {
        return RectF(x - width / 2 + 10, y - height / 2 + 10,
                     x + width / 2 - 10, y + height / 2 - 10)
    }

    fun hit() {
        lives--
        if (lives <= 0) {
            isAlive = false
        } else {
            weaponLevel = 1
            // 触发无敌时间（3秒）
        }
    }

    enum class WeaponType {
        VULCAN, LASER
    }
}
```

### 8.3 碰撞检测系统（Kotlin）
```kotlin
object CollisionDetector {

    fun checkPlayerEnemyCollision(
        player: Player, 
        enemies: List<Enemy>
    ): List<Enemy> {
        val playerHitbox = player.getHitbox()
        return enemies.filter { enemy ->
            RectF.intersects(playerHitbox, enemy.getHitbox())
        }
    }

    fun checkBulletEnemyCollision(
        playerBullets: List<Bullet>, 
        enemies: List<Enemy>
    ): Pair<List<Bullet>, List<Enemy>> {
        val hitBullets = mutableListOf<Bullet>()
        val hitEnemies = mutableListOf<Enemy>()

        for (bullet in playerBullets) {
            for (enemy in enemies) {
                if (RectF.intersects(bullet.getHitbox(), enemy.getHitbox())) {
                    hitBullets.add(bullet)
                    hitEnemies.add(enemy)
                    break
                }
            }
        }
        return Pair(hitBullets, hitEnemies)
    }

    fun checkEnemyBulletPlayerCollision(
        enemyBullets: List<Bullet>, 
        player: Player
    ): List<Bullet> {
        val playerHitbox = player.getHitbox()
        return enemyBullets.filter { bullet ->
            RectF.intersects(bullet.getHitbox(), playerHitbox)
        }
    }

    fun checkPlayerPowerUpCollision(
        player: Player, 
        powerUps: List<PowerUp>
    ): List<PowerUp> {
        val playerHitbox = player.getHitbox()
        return powerUps.filter { powerUp ->
            val distance = Math.hypot(
                (player.x - powerUp.x).toDouble(),
                (player.y - powerUp.y).toDouble()
            )
            distance < 50 // 拾取范围
        }
    }
}
```

## 十、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 同屏子弹过多导致掉帧 | 高 | 使用对象池复用子弹对象，减少GC |
| 碰撞检测性能问题 | 高 | 空间分割（四叉树/网格），只检测附近对象 |
| 不同分辨率适配 | 中 | 使用相对坐标，多分辨率测试 |
| 触摸操控不够精准 | 中 | 提供操控灵敏度设置，支持多种操控模式 |
| 内存占用过高 | 中 | 及时释放不用的Bitmap，使用纹理图集 |
| 美术资源进度延迟 | 中 | 先用占位图开发，后期替换 |
| 项目超期 | 低 | 优先完成核心玩法，非核心功能可延后 |

## 总结

这份开发计划完整覆盖了从项目搭建到最终发布的全流程，遵循原版雷电的核心设计理念，同时针对移动端进行了适配优化。建议按阶段逐步开发，每个阶段完成后进行测试验证，确保核心玩法的完整性和流畅性。

**核心开发原则**：
1. **先核心后周边** - 优先完成战机操控+射击+敌人生成的基础循环
2. **先功能后美术** - 用占位图快速验证玩法，后期替换正式美术资源
3. **持续测试优化** - 每完成一个阶段就在真机上测试性能和体验
4. **保持街机手感** - 操控响应要快，爆炸要有冲击力，BGM要燃

祝你开发顺利，打造出一款让老玩家 nostalgic、新玩家上头的优秀雷电致敬作品！
